# The gate has been red for so long that its exit code stopped meaning anything
# and a real regression could sit in the pile unseen for days (#124). The cost is
# not only hidden bugs: `break_metal` was one author's own failure sitting here
# being read as somebody's background noise, so an unreadable gate does not just
# hide a bug, it launders who owns it.
#
# `tools/check.sh` diffs the run against this list and reports:
#   NEW     a failure not on this list -- yours, almost certainly, and the gate
#           fails on it even though the run was red before you started
#   FIXED   a line here that passed -- take it OUT in the same commit
#
# THE RULES THAT KEEP THIS FROM BECOMING A PLACE TO PUT FAILURES:
#   1. A line goes in only with a cause written next to it in the commit
#      message. "Known red" is not a cause.
#   2. FIXED lines come out the same day they go green, or the list drifts and
#      stops being able to fail.
#   3. This list is evidence about ONE tree at ONE moment. Regenerate it, do not
#      hand-edit it, when the suite's shape changes -- several tests grow
#      1300-tile worlds and shard composition moves with them.
#
# **AND IT MUST BE REGENERATED THE WAY THE GATE RUNS: SHARDED.** The set this
# replaced was taken from a single-process run and compared against a sharded
# one, which is not a comparison -- different partitioning means different
# neighbours, so an order-dependent failure differs for reasons that are nobody's
# code. One failure moved for exactly that reason and cost an A/B to clear.
#
# Regenerate with:
#   for i in 0 1 2; do godot --headless --path . -s tests/run.gd -- --shard=$i/3; done
# collecting the FAIL lines, stripping "FAIL " and the timing, sorted unique.
